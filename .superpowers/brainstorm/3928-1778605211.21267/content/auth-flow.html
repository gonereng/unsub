Auth Flow — NextAuth + Dual-Purpose OAuth

The same OAuth token is used for both authentication AND inbox access. This means one consent screen for the user, one token to manage.

OAuth Scopes Requested

Google

openid email profile
(auth / user info)

https://www.googleapis.com/auth/gmail.readonly
(read inbox)

https://www.googleapis.com/auth/gmail.settings.basic
(create filters for blocking)

https://www.googleapis.com/auth/gmail.labels
(move digest emails to folder)
Microsoft

offline_access openid profile
(auth + refresh token)

Mail.Read
(read inbox)

Mail.ReadWrite
(move/filter emails)

Auth Flow Steps

1
User clicks "Sign in with Google/Microsoft"
2
OAuth consent screen requests auth + mail scopes
3
NextAuth receives callback, stores tokens in Account table
4
On callback: trigger initial inbox scan job (BullMQ)
5
Set up Google Pub/Sub push notification (or MS webhooks)
6
User lands on dashboard — scan runs in background

Kill Switch (Revoke)

How it works:
1. User clicks "Revoke Access" in settings
2. POST to https://oauth2.googleapis.com/revoke?token={token}
3. Delete Account + Subscription + ActionLog + Digest records
4. User stays logged in (can re-connect later)

This satisfies both the "kill switch" feature and GDPR data deletion requests.

Token Refresh Strategy

  • NextAuth's built-in JWT callback refreshes tokens automatically
  • If refresh fails (e.g., user revoked access externally), mark Account.active = false
  • Show a banner on dashboard: "Reconnect Google account to resume scanning"

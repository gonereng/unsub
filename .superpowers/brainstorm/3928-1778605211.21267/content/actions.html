Email Management Actions

One-Click Unsubscribe

For each subscription with List-Unsubscribe header:

mailto: variant → send email via provider API (Gmail: users.messages.send)
http/https variant → fetch(url, { method: "POST" }) or GET
No header → fallback: extract unsubscribe link from HTML body (regex)

→ Log in ActionLog (action: "unsubscribed")
→ Optionally add sender to Block list if unsubscribe fails (verified by checking next email)

All done server-side in a BullMQ job so the UI is not blocked.

Bulk Unsubscribe

User selects 50+ subscriptions → clicks "Unsubscribe All"

→ Enqueue one BullMQ bulk-unsubscribe job
→ Job processes items in parallel (batch of 10)
→ Real-time progress via WebSocket (or polling)
→ Each item: same logic as one-click
→ On completion: show summary "45 succeeded, 5 failed — retry?"

Rate limiting: 5 req/s per provider to avoid 429 errors.

Block Sender

For senders that ignore unsubscribe requests (or malicious senders):

Gmail: users.settings.filters.create — filter that sends future mail to Trash
Outlook: POST /me/mailFolders/Inbox/messages/move + rule creation

→ Set Subscription.isBlocked = true
→ Log in ActionLog (action: "blocked")
→ Future emails from this sender auto-routed to Trash at provider level
Block and whitelist are mutually exclusive toggles.

Keep / Whitelist

User toggles a subscription as "safe":
→ Set Subscription.isWhitelisted = true, isBlocked = false
→ Scanner skips this sender on future scans
→ Subscription still appears in the list (with "whitelisted" badge)
→ User can undo anytime
This does NOT create a provider-side filter — it only affects scan behavior.

Daily Digest / Rollup

How it works:

1. User marks a subscription as "rollup"
2. Worker checks DigestConfig for schedule
3. At scheduled time: fetch new emails from rolled-up senders
4. Generate HTML digest (subject, snippet, original link)
5. Move original emails to a hidden label/folder ("Unsub/RolledUp")
6. Send digest email to user's inbox via provider API

Or send via a transactional email service (Resend/SendGrid) for better formatting.

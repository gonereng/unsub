Advanced Features + Infrastructure

Unsubscribe Fallback

~30% of marketing emails lack proper List-Unsubscribe headers.

Fallback logic:
→ Scan HTML body for /unsubscribe|opt.?out|cancel.?subscription/i
→ Extract the nearest <a href="..."> surrounding the text
→ Verify it's a valid URL
→ Open in an iframe or redirect user (since links often need cookies/session)

If no link found → offer Block Sender as alternative + mark for manual review.

Financial Protection

Before executing unsubscribe/block, check sender against protected keywords:

receipt, invoice, payment, bank, flight, booking, confirmation, statement, billing, ticket, order

If match → show warning modal:
"This looks like a transactional email (receipt/flight/order). Unsubscribing may cause you to miss important updates. Continue anyway?"

User can dismiss warning and proceed. Log it in ActionLog metadata.
Phase 2: lightweight LLM check for higher accuracy.

BullMQ Background Jobs

Queues:
├── scan-inbox — Initial + full inbox scan
├── scan-recent — 6-hourly re-scan for new emails
├── bulk-unsubscribe — Batch unsubscribe (10 items/job)
├── single-unsubscribe — One-click unsubscribe
├── generate-digest — Generate daily/weekly digest email
└── send-digest — Send generated digest via provider API

Repeatable jobs (cron):
├── Every 6h → scan-recent for all active accounts
├── Daily at 08:00 → generate-digest for all daily users
└── Sunday at 09:00 → generate-digest for all weekly users

Worker process runs separately from Next.js, sharing Prisma client + Redis connection.

Deployment — Docker Compose

services:
  app:       # Next.js app (UI + API routes)
    build: .
    ports: ["3000:3000"]
    depends_on: [db, redis]

  worker:    # BullMQ worker process
    build: .
    command: node worker/index.js
    depends_on: [db, redis]

  db:        # PostgreSQL
    image: postgres:16
    volumes: [pgdata:/var/lib/postgresql/data]

  redis:     # BullMQ backend
    image: redis:7-alpine

  # Optional: nginx reverse proxy for TLS + domain

Single Dockerfile builds both app and worker. nginx handles HTTPS termination. Environment variables for secrets (DB URL, Redis URL, OAuth client IDs, etc.).
